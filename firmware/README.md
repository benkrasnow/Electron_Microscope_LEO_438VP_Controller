# LEO 438VP control box firmware (Teensy 4.0)

This firmware replaces the control part of the original image-processor board and the Win98 PC. It owns machine state and safety for:

- the EHT / gun supply;
- the stage / vacuum controller;
- the VP controller;
- the EO board (scan and lenses).

It runs on the control box in `hardware/leo_control_box`. The OBI still does the imaging. The PC talks to the box over USB ([PROTOCOL.md](PROTOCOL.md)), and the 4.3″ touch display shows the state and offers the main buttons.

Status (2026-11-14): **v0.1.0. It compiles for Teensy 4.0 (Teensyduino 1.62) but has not run on hardware.** Every timing and value comes from the captures in `specifications/`. Bring-up steps are below.

## Build and flash

- Teensyduino (Arduino IDE 2 with the Teensy package), board **Teensy 4.0**, USB type **Serial**, CPU speed **600 MHz**. Only core libraries are used (SPI, LittleFS, IntervalTimer).
- From the command line, run this in `firmware/`:
  ```
  arduino-cli compile --fqbn teensy:avr:teensy40:usb=serial,speed=600,opt=o2std leo_control
  ```
  `arduino-cli.exe` ships with the Arduino IDE under `resources/app/lib/backend/resources/`.
- After the first flash, the `bootloader` USB command enters the loader, so the button on the Teensy is not needed.

## How it is organised

The main loop never blocks. Each link module owns a `Link` that sends one command at a time and parses the reply into module state. Modules compare their state with the wanted state (the `op.*` settings) and send whatever differs. A USB command or a touch button therefore just changes a setting or starts a machine sequence; the modules do the rest.

Nearly every number is a setting:
- timings;
- ramp steps;
- thresholds;
- calibrations;
- link polarities;
- joystick gain;
- display backlight.

Change them with `set name value` over USB. They are saved to flash 3 s after the last change, at a moment when no link is waiting for a reply, so a flash write cannot lose a reply byte. Firmware updates keep saved values and pick up new defaults for everything never changed.

## Safety rules enforced by the firmware

| Rule | Where |
|---|---|
| Beam on only with vacuum ready (`SPVR`, all `.VS` inhibits released), EHT status OK, VP controller settled (state 3 or 9), and no pressure change running | `Machine::beamOn` |
| **Filament off and cooled before any pressure change.** Vent, VP enter, VP exit and a VP target change first run the full beam-off (filament ramp-down) and then wait `eht.fil_cool_s` | `Machine::coolStep` |
| Vent order: beam off → cool → leave VP if needed → Z down to 0.5 mm (stage homed) → `.VL V` → VP `TO 2` at `NSP` | `MO_VENT` |
| Filament ramps (up ~15 s, down ~9 s) and kV ramp above 20 kV, as LEO-32. The filament current is set low before the filament supply bit is switched on | `Eht::runSeq` |
| `.B000` before the EHT goes off; detectors off before EHT off | `SQ_OFF`, `SQ_EHTOFF` |
| Vacuum lost with the beam on: all supplies cut at once (`sys.vacloss_abrupt`; 0 = ramp instead) | `Machine::monitors`, `Eht::handleStatus` |
| EHT fault (reset, trip, filament blown): supplies cut, `.R`, beam stays off until asked again; settings re-sent once the status is clean | `Eht::handleStatus`, `reconcile` |
| Scintillator HV off while the chamber is in VP (`eht.scint_off_vp`, default on, as the original firmware) and while inhibited | `Eht::idleWord` |
| VP: `HP` and `MC` always sent before `TO 7`. `GP` every 4 s keeps the 360 s watchdog fed; a controller back in POWER_UP is handshaken again. Gas reaching the column (Penning leaves `SP`/`SPVR` during VP) → `TO 10` | `Vp`, `Machine::monitors` |
| Stage: user limits re-sent on every vacuum change (X/Y 35–65 mm at air); go-to clamped to them; moves refused until homed (`stg.req_home`); loss of position detected | `StgVac` |
| EO: range relays only switch with the coil weights parked (park → range → 45 ms → weights) | `Eo::applyOptics` |
| Raw link commands only with `dbg.raw = 1` | `usb.cpp` |

**Restarts.** The beam state is kept in flash (`state.beam`). If the Teensy restarts (firmware upload, `reboot`, power glitch) while the beam is on, it reads `?S` first:
- If the EHT set did not reset, it **adopts** the running beam and re-sends the same setpoints.
- If the set reset, or the restart happened in the middle of a ramp, it cuts the supplies.

The VP controller is adopted in whatever state it is in. No `RE 0` / `RE 1` is sent, because either could open V8 under gas. The EO board gets its full state again within milliseconds. The filament cool-down timer survives restarts through the RTC.

**USB.** The PC link is optional at all times. Nothing waits for it, and plugging or unplugging changes nothing. The display and the three buttons keep working without it.

## Touch screen

- **Header:** machine summary and clock.
- **Message line:** the running sequence, or the reason a button was refused.
- **Three panels:**
  - Vacuum / VP: state, Penning pressure, inhibits, VP state, chamber Pa.
  - Beam: state, kV, emission, filament, collector, EHT status, cool-down.
  - Stage / scan: X Y Z T R, initialised, scan mode, magnification.
- **Link indicators:** EHT, STG/VAC, VP, EO, PC.
- **Six buttons:** PUMP, VENT, BEAM ON, BEAM OFF, ENTER VP / LEAVE VP, and a red STOP.
  - A button acts when it is released. STOP acts as soon as it is pressed.
  - Buttons whose interlocks are not met are greyed. Touching one shows the reason.
  - VENT and the VP buttons ask for confirmation (`ui.confirm`).

## Front-panel buttons

| Setting | Default action |
|---|---|
| `btn.1` | red: **safe**, the same as STOP: abort the sequence, stop the stage, beam off |
| `btn.2` | stage stop |
| `btn.3` | none |

Action codes: 0 none, 1 safe, 2 beam on, 3 beam off, 4 stage stop, 5 EHT off, 6 abort.

## Bring-up checklist (first power-on with the SEM)

1. **USB only, no fibers.** Check `hello`, `list`, the display, the buttons (`btn` in the status) and the status LED. The LED blinks fast while links are down.
2. **Polarities.** The HFBR-2521Z receivers pull low when lit, so `*.rx_inv = 1` is the default. If a link shows no replies with `trace all`, try flipping `eht.rx_inv` / `stg.rx_inv` / `vp.rx_inv` / `eo.rx_inv`, and the matching `*.tx_inv`. The VP board's fiber idle polarity is still unconfirmed.
3. **Stage / vacuum first.** `trace stg`, then check that the start-up configuration matches the capture (`STAGE_VACUUM_INTERFACE_SPEC.md` §6.1) and that `.VT` / `.SD` polling runs.
4. **VP.** DIP switches 2 and 4 ON, 1 and 3 OFF. Check that the handshake adopts the current state and that `GP` runs every 4 s.
5. **EHT with the vacuum at air.** Expect `=2058`-style status, `.O0407`, and `beam on` refused.
6. **EO.** `eo r 3 13` should return the last options value written (252 / 244). `eo.link` goes true. Then check `mag`, `focus` and `stig` with the OBI image.
7. **Pump, beam on at 5 kV, beam off, VP enter / exit, vent.** Compare `trace` output against the captures.
8. **Internal raster** (`scan raster`): check F1 / F2 on the scope against `SCAN_GENERATOR_INTERFACE_SPEC.md` §2.1, and whether `scan.trim_ppm` is needed to stop the Y step from drifting through the X line.

## Known limits / open items

- No hardware test yet. The EO bit-banged timing (162.8 CPU cycles per bit, 0.16 % of the rate) and the F4 reply sampling need a scope check.
- Condenser values are set directly (`cond`). There is no Optibeam lens model yet, so probe current is controlled through the condenser DACs.
- `eo.wd_rot` sign and `eo.wd_exp` come from one WD change (10 → 15 mm); verify them.
- The per-range scan calibration (`eo.k*`, `eo.d*`, `eo.ky*`, `eo.e*`) was fitted from the captured weights at WD 15 mm, assuming the captures were taken at `eo.kv_ref` = 20 kV.
- The EHT fault bits 0x04 / 0x02 are as in the original firmware and have not been seen on the wire.
- Reduced-area, split-scan and averaging modes are not implemented (the OBI does imaging).
- Flash writes (settings saves) may stall the internal raster for one line.
