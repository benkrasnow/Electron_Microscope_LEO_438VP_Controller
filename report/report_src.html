LEO 438VP control computer: how LEO-32 talks to the ISA image-processor board and the fiber links

A static analysis of the drive image, done without running any code. It traces the path from the LEO-32 user interface down to the bytes on the fiber-optic serial links, lists every command table that survived in the binaries, and proposes a staged plan for replacing the Win98 PC and its custom ISA board.

1Key findings

The boardA TMS34020 graphics processor is the real controller

The ISA card is the Cambridge/Leica "Stereoscan Image Processor": a TI TMS34020 GSP running the TIGA graphics manager plus LEO's own multitasking kernel and ten loadable modules. The PC never touches the fiber links directly. It sends TIGA function calls to the GSP, and GSP code drives the links.

ISA resourcesI/O 0xA300–A301 page registers + 32 KB memory window at D000:0000

Each GSP address is reached by writing bits 31–18 to two page registers and then doing a 16-bit access in the D0000h window. Probably IRQ 9 for GSP→host interrupts.

Fiber links 1 & 2Two 16550-type UARTs, 9600 baud 8N1, ASCII "dot commands"

UART A (GSP 0x60300000) talks to the EHT/gun supply. UART B (0x60380000) talks to a combined Stage/Vacuum comms CPU. Commands look like .SX, .VL, .B, terminated by CR/LF.

Scan / opticsA DSP behind dual-port RAM runs the scan and the EO board

The electron-optics module never uses a UART. It writes EO registers through a DSP, which also generates the 1024×768 raster. The DSP's variable map survives as a commented text file (SEM_INIT.DAT).

SymbolsThe GSP modules still carry their symbol tables

Every function and global in the ~3 MB of GSP code is named (_InitEHTUART, _send_stage_command, _DSPISR…). This makes full decompilation practical.

HealthThe machine is logging EHT-link timeouts

The live log (to 15 Jul 2026) has 95 "EHT set comms timeout" events, two "Filament Blown" errors and repeated Penning-gauge warnings. The EHT fiber link is the first one to scope.

2System architecture

The PC is a host for one large ISA card. The card owns the video path, the scan generator, and the serial links to the column electronics. The PC's own S3 VGA output goes into the card and comes back out mixed with the live SEM image. Vacuum control in VP mode is the one exception: it runs from the PC's own COM2 to a separate "Orsay" controller board.

3Software stack

LEO-32 is a 32-bit shell (MFC and Visual Basic 6) wrapped around a 16-bit core written for Windows 3.1 between 1994 and 1996. A call from the UI crosses a 32→16-bit flat thunk, passes through one of eight "controller" DLLs, and is turned into a TIGA extended-function call that runs on the GSP.

4PC ↔ board ISA interface

There is no Windows VxD or kernel driver for the board. The hardware is set up from DOS in AUTOEXEC.BAT, before Windows starts, and Windows code then reaches it through the resident TIGA communication driver. The small DOS tools in C:\GSPUTILS (Borland Turbo C, 1993) contain the clearest copy of the raw access routine.

Window addressing

TMS340 processors use bit addresses. The window covers 218 bits (32 KB), so the page registers carry GSP address bits 31–18 and the low bits become the offset inside the window. Recovered from GSPHALT.EXE:

/* write one 16-bit word to GSP bit-address A (reconstructed from GSPHALT.EXE @0x265) */
void gsp_poke16(uint32_t A, uint16_t v) {
    outb(0xA301, (A >> 24) & 0xFF);          /* GSP addr bits 31..24              */
    outb(0xA300, (A >> 16) & 0xFC);          /* bits 23..18 (bits 17,16 ignored)  */
    *(volatile uint16_t far *)MK_FP(0xD000, (A >> 3) & 0x7FFF) = v;
}
/* GSPHALT: poke(0xC0000100, 0xC300) then poll bit 4 of the same register up to 1000 times
   → writes the GSP's own host-control register (HSTCTLH) through the window to halt it. */

Boot sequence (from AUTOEXEC.BAT → LEOEXEC.BAT C:)

  1. MCS2GSP C:\GSPUTILS\MMLCA.MCS: resets the Xilinx LCAs on the memory module, clocks in the Intel-hex bitstream (349 lines), and checks DONE.
  2. GSPHALT: halts the TMS34020 through its host-control register.
  3. EPROM OFF: moves the board's boot EPROM from GSP 0xFFF00000 to 0xEFF00000 so TIGA can own the vector area.
  4. TIGACD: installs the TIGA Communication Driver TSR (reads TIGA.CFG: board "LEO 400 Series 16 Colour Board 1024x768 60Hz").
  5. TIGALNK -lx: loads TIGAGM.OUT (graphics manager + LEO kernel) and starts it. On failure it prints "SEM INITIALIZATION FAILURE".
  6. In Windows, SEM_INIT.EXE (1996) loads TIGAWIN.RLM, downloads DPRAM.IMG to the DSP, replays SEM_INIT.DAT, and turns its "traffic light" green.
  7. leoserv.exe loads M007…M800, and each loads its GSP extension with TIGALNK-style relocation (install_rlm), getting back a module ID.

5Inside the board: GSP address map and runtime

The GSP runs TI's TIGA 2.20 graphics manager, extended with a small preemptive kernel (_Spawn, _Suspend, _Activate, _PutQueue/_GetQueue, _Announce/_Expect). Each module spawns a process (_ProcEHTCmds, _ProcStgVacCmds, _ProcDSPCmds, _EO_Process…) that owns its hardware. Host calls drop commands into that process's queue, and replies come back through response buffers (EhtTigaRsp, StgRspBuff…), which the host polls.

Peripheral addresses below come from 32-bit immediates in the GSP code and are not relocated, so they are fixed hardware addresses. TMS340 addresses are bit addresses; divide by 8 for a byte address.

UART initialisation (decoded from TMS340 machine code)

; _InitEHTUART (g100.440 @0x1EBB0) — register n is at base + 32·n bits
MOVI  0x60300000, A0
MOVB  0x80 → *A0(96)    ; LCR = 0x80   DLAB on
MOVB  0x0C → *A0(0)     ; DLL = 12
MOVB  0x00 → *A0(32)    ; DLM = 0      divisor 12 → 9600 baud at 1.8432 MHz
MOVB  0x03 → *A0(96)    ; LCR = 8N1
MOVB  0x05 → *A0(32)    ; IER = RX data + line status
MOVB  0x08 → *A0(128)   ; MCR = OUT2 (IRQ enable)   [UART B uses 0x0A: OUT2 + RTS]
; _TxEnable: IER |= 0x02 when a message is queued; the ISR reads IIR (+64) and LSR (+160)

The baud rate assumes the standard 1.8432 MHz UART crystal. If the board uses a different clock, the divisor of 12 still pins the ratio, so a scope on the fiber receiver will settle it in seconds.

6Command tables (host → GSP)

Every TIGASEM.DLL export is a thin stub that pushes its arguments and issues one TIGA extended call. The command word is the module ID that TIGALNK assigned at load time, ORed with 0x4000 and the function's index in that module's .TIGAEXT table. Two spot checks agree: READDPRAM sends id|0x4006, and entry 6 of g900.rlm is _cp_read_dpram. WRITEEO sends id|0x400B, and entry 11 is _cp_write_eo. The tables below are read from the relocation records of each module, so the index-to-function mapping is exact.

Entries 0 and 1 are usually the module's own init/entry point. These tables are also the natural API surface for a new host driver if the existing board is kept (path B in §11).

9Other interfaces worth knowing

  • VP / "Orsay" controller (hpapp.exe, 1998): PC COM2:9600,n,8,1. Commands seen: RE 0 reset, ST 1,%d to ST 5,5 timeouts, TO %d, HP %d,%d,%d pressure target, MC 100,900. It has its own state names (AT_AIR_HP, PUMPING_LP, GOING_TO_HP…), a debug log option, and OrsayBoardTimeout=300 in C:\WINDOWS\LEO.INI.
  • Licence dongle: DESkey DK2 on the parallel port (DK2WN95.386, DK2WIN32.DLL imported directly by leoserv.exe). M600 stores the serial number and licence bits on it ("Re-write Licences to Dongle"). A backup copy lives in C:\LEO\data.dgl if present. HASP and Hardlock drivers are also installed, probably for third-party software.
  • RemCon32: LEO's documented RS-232 remote-control protocol (remcon32.exe, REMCON32.HLP). It drives the whole stack from outside and is a cheap way to script repeatable actions while capturing the fiber links.
  • DDE / LEOAPI.OCX: the same parameter set is reachable by DDE and by an ActiveX control used by EDS vendors (Oxford ISIS, Link, iXRF).
  • Calibration data: C:\LEO\*.VAC (vacuum NVRAM copies), gamma2.dat and loc*/loi*.dat (HRRU photo tables), L500.INI (filament limits, VP target 9, VP limit 274), and the Access database LEO_USER.MDB (users, apertures, column calibration). A replacement system needs these values even if none of the code is reused.

10Notable findings on this install

EHT link faults are current. LOG\leolog.leo runs from 01-01-2025 to 15-07-2026 and contains 95 "EHT set comms timeout" events, "EHT – Filament Blown" on 10 and 13 July 2026, 20 "EHT – Spurious Reset", and repeated "Vacuum system Penning Gauge Failure" warnings. Timeouts on UART A could be a degrading fiber, transceiver, or the EHT unit itself.
A 69.5 MB log. LOG\Copy of leolog.leo (Feb 2003 – May 2024) holds about 510,000 alternating "EHT Set Extractor Trip" / "EHT Set Emergency Rundown" errors (numbers 519/520), roughly every 10 minutes for long periods. That is a long-standing EHT fault condition and a log that grew without limit. Free disk space is logged at 465 MB.
  • The log restarts at 01-01-2025 13:24. That looks like the CMOS clock being reset (flat battery or a CMOS clear) before the current log began.
  • Software lineage. The board and DSP code descend from the Cambridge Instruments / Leica Cambridge Stereoscan S300 era (1992). The GSP manager reports "S300 Image Processor Board", TIGACD says "Stereoscan Image Processor", and the EO DLL is labelled "S420/430". LEO-32 V02.04 (June 2001) is a 32-bit shell on 1994–96 Win16 DLLs.
  • Symbols left in. All GSP COFF modules keep full symbol tables, and the Win16 DLLs export by name. This is unusual for a commercial product and makes the next reverse-engineering stage much easier.
  • Display driver changed. SYSTEM.INI now uses an S3 Trio64V+ PCI driver; LEO.BAK shows the factory STB PowerGraph 64. The board's VGA pass-through and "mix delay" calibration depend on the VGA timing, so keep the current card in mind if anything is swapped.
  • Networked Win98. AUTOEXEC.SYD adds a route to gateway 143.242.77.1, upgrade.txt lists shares of drives A: through G: with custom permissions, and there are 16 Windows password-list (.PWL) files, NetDrive, Firefox, and AVG 7 / McAfee remnants (quarantine file AVG7QT.DAT). Win98 PWL encryption is weak, so treat any reused passwords as exposed. If the machine is still on a network, take it off.
  • A Windows 2000 upgrade was attempted (upgrade.txt, WINNT32.LOG). LEO-32 under Win98 depends on direct real-mode TSR access and 16-bit thunks, so an NT-family upgrade would have broken it.
  • Startup is fragile. AUTOEXEC.BAT must run LEOEXEC.BAT C: before Windows. The Grisoft AVG boot scanner line has been commented out above it.
  • Root-level oddities. 50.exe is a Macromedia Director "Projector" (a self-running presentation, read-only). Restoring All Your Files.doc is a stock Windows backup help page, not a ransom note. dlgsetup11_win.zip holds a 2006 Setup.exe of unknown purpose. None of these looked malicious in a strings pass, but none were executed or scanned.
  • Useful documentation is on the disk. help\english\MAINT.HLP, LEOSERV.HLP, OPERATION.HLP, STAGE.HLP and REMCON32.HLP are service-level WinHelp files. They are worth decompiling (e.g. with helpdeco) for calibration procedures and error meanings.
  • User and backup data. 20+ user profiles under LEO-32\user (macros, state files, annotation sets) and dated database backups from 2000 to 2011 in C:\Backups. The share\ folder holds about 80 TIFF images (1024×768).

11Replacement paths

The board does three separate jobs: serial links to slow subsystems, real-time scan generation with image acquisition, and display. These can be replaced at different speeds. The recommended order goes from cheapest-to-verify to hardest.

Stage 2 · capture and confirm · low risk

A. Instrument the fiber links before changing anything

  • Identify the fiber connectors and transceivers on the board (likely HP/Agilent HFBR "Versatile Link" plastic fiber or ST glass). Build passive taps or receive-only adapters to TTL, then into a USB logic analyser or USB-UART adapters.
  • Confirm 9600 8N1 on the two UART links and log full sessions: power-up, stage init, pump/vent, EHT on, filament ramp. Correlate the log with the .S?/.V?/EHT character tables above.
  • For each remaining fiber, measure the bit rate and framing. Expect higher-speed synchronous or Manchester data for scan and video.
  • Use RemCon32 or macros to repeat single actions, and the EHT direct-command service panel to probe the EHT unit by hand.
  • Disassemble the GSP modules with MAME's unidasm (it supports tms34010 and tms34020) or a Ghidra TMS340 processor module. With the symbol tables applied, _send_stage_command, _decode_vac_status and _interpret_cmd_response will give exact argument formats.
  • Image the drive and dump the board's EPROM and LCA bitstream before any hardware change. Read and save the DESkey dongle contents.
Stage 3 · modern PC, existing board · medium risk

B. Keep the ISA board, replace the PC and software

The interface is simple: two page registers and a 32 KB window. A modern host can drive the board through an industrial PC with an ISA slot, or through an LPC/PCIe-to-ISA bridge.

  • Write a small user-space driver for 0xA300/0xA301 and the D0000 window. Reproduce the boot steps (LCA load, halt, EPROM off, load TIGAGM.OUT).
  • Write a COFF loader for the existing g*.rlm / .440 modules, or call into them through TIGAGM. Then invoke the documented .TIGAEXT functions by index. This reuses the proven real-time firmware and moves only the UI.
  • Fallback during development: run the original Win98 image on the new ISA-capable PC as a known-good reference.
Stage 4 · new hardware · higher risk

C. Replace the board with a new controller

  • Slow links first. The EHT and Stage/Vac links are 9600-baud ASCII. A microcontroller or a PC with two fiber-to-UART adapters can take them over early, gated by a supervisor that keeps the original interlocks (vacuum state machine, beam-off-before-vent, stage touch alarm).
  • Scan and acquisition. An FPGA board (for example a Zynq or a small FPGA with a USB3 or Ethernet bridge) generates the raster, drives the scan/EO link in whatever format Stage 2 finds, and digitises or receives detector video. The DPRAM variable map defines the feature set to match: 16 scan origins and amplitudes, dual-mag, stereo, line and frame integration, freeze, spot mode.
  • Display and UI on a normal PC. With the frame store in the FPGA or on the host, overlay mixing is no longer needed and the VGA pass-through disappears.
  • Calibration carry-over. Port the lens and mag calibration math in M200.DLL/g200.440 (C1/C2/C3 cal and rem values, mag tables, scan orthogonality) and the stored values from LEO_USER.MDB and config.LEO.
Recommendation. Do path A now. It is cheap, it tells you whether the EHT timeouts are a link problem, and it decides whether path B is worth doing. If the scan and video fibers turn out to be simple, go straight from A to C and skip the bridge work in B.
