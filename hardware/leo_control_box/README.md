# LEO 438VP control box (KiCad 10 project)

Microcontroller board that owns the SEM's machine state and safety, independent of the PC: EHT and stage/vacuum fiber links, VP RS-232, the EO board's four fibers (register link plus the internal-scan backup), a spare I²C expansion port, sync outputs to the OBI, and a 2×10 IDC header for a 4.3″ 800×480 touch display (Newhaven NHD-4.3-800480FT-CSXP-CTP, FT813 EVE). (PMT signal and gain are handled by separate hardware.) Interface specs: `../../specifications/`.

Status (2026-11-13): **schematic rev 0.1 drawn, ERC clean (0 violations).** PCB not started; the board outline is still the 160 × 100 mm template.

The schematic is generated by `tools/build_schematic.py` (one A2 sheet in functional blocks: power, controller, 5 fiber transmitters, 3 fiber receivers, VP RS-232, I²C, OBI sync). Connections are made with net labels and power symbols placed on the pin ends; each MOSFET gate sits directly on its buffer output. **Re-running the script overwrites the schematic**, so either keep editing the script, or switch to hand-editing in KiCad once the circuit is settled (and stop using the script).

## Teensy 4.0 vs 4.1

The 4.0 works. It has everything this board needs on its 24 edge I/O pins: 7 hardware UARTs (we use 3), FlexIO1 on pins 2–5 for the EO frames, I²C on 18/19, and spare pins. It lacks the 4.1's Ethernet, so the PC link is USB. To keep a PC or USB reset from resetting the controller, **cut the Teensy's VUSB–VIN pad link and power it from the board's 5 V** (the Teensy does not reset when a serial port is opened). Use a 4.1 only if Ethernet isolation from the PC becomes a requirement.

Teensy 4.x pins are **3.3 V only (not 5 V tolerant)**: every 5 V signal must be level-shifted (see the receivers below).

## Circuit notes

**Fiber transmitter channel (×5).**
Teensy pin → 74AHCT125 gate (VCC = 5 V, OE tied low; its TTL input thresholds accept 3.3 V) → 2N7002 gate → HFBR-1521Z cathode. The anode goes through a current-setting resistor to +5 V (≈ 56 Ω for ~55 mA; set from the datasheet's recommended drive for 5 MBd). Add a footprint for the datasheet's peaking capacitor across the resistor.
- Logic high = LED on = line idle, which matches all links (idle high).
- **10 kΩ pull-up to 3.3 V on each AHCT input**, so the lines idle high (no false start bits) while the Teensy is in reset or being programmed.

**Fiber receiver channel (×3).**
HFBR-2521Z VCC from +5 V, with the decoupling/filter network recommended in the datasheet. VO is an open-collector output: pull it up to **3.3 V** (1 kΩ) and connect it straight to the Teensy pin, leaving RL (the internal 5 V load resistor) unconnected. That keeps the Teensy pin at a safe 3.3 V level. Check the rise time against the 271 ns EO bit period on the first board (~15 pF × 1 kΩ ≈ 15 ns, fine).

**VP RS-232.**
MAX3232 at 3.3 V with 4 × 0.1 µF charge-pump capacitors plus bypass. Wire it as a DTE port like the PC's COM2: T1OUT → DE-9 pin 3 (TXD), DE-9 pin 2 (RXD) → R1IN, pin 5 GND. Only TXD/RXD were ever used.

**I²C.**
3.3 V bus with 2.2 kΩ pull-ups on two Qwiic sockets, kept as a spare expansion port (no devices on board).

**Power.**
5 V from either the terminal block J1 or the USB-C receptacle J10 (both feed +5V_IN; **use one at a time**, they are not isolated from each other) → PTC fuse → +5 V rail (HFBR parts, AHCT drivers, Teensy VIN). The Teensy's 3.3 V regulator feeds the MAX3232 and the pull-ups (it can supply ~250 mA).

## USB-C power input (added 2026-11-14)

J10 is a power-only USB-C receptacle (GCT USB4125-GF-A, 2073-USB4125-GF-ACT-ND, $0.61). VBUS goes to +5V_IN, ahead of the PTC fuse, in parallel with the terminal block J1; the shield and GND go to ground. CC1 and CC2 each have a 5.1 kΩ pull-down (R65, R66), which identifies the board as a USB sink, so USB-C-to-C chargers switch on their 5 V output. USB-A wall adapters with an A-to-C cable supply 5 V regardless.

- No PD controller: the board only ever gets 5 V. It does not read the charger's advertised current (Default / 1.5 A / 3 A), so use an adapter rated **at least 1.5 A** (the board draws about 0.65 A with the display).
- **Use J1 or J10, not both at once**: the two inputs are tied together without diodes.
